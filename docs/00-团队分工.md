# 00 · 多 Agent 面试协同团队分工

> 岗位：后端开发工程师（校招）　企业：恒信数字科技有限公司　版本：v1.0
> 依据：`.codeartsdoer/skills/ai-interview-swarm`（编排器 + 三名面试官 + 评估官）与 `knowledge/` 四份知识库
> 原则：**单线程、单发言人、逐段交接、数据不改写**。同一时刻只允许一个角色对候选人说话。

---

## 一、团队总览

| 角色 | Agent 代号 | 对应技能包 | 一句话使命 | 面向对象 |
|---|---|---|---|---|
| 初面官 | `ORCH-INIT` | `interview-orchestrator` + `general-chat-officer` | 控流程、验材料、破冰、初筛、把好入口 | 候选人（唯一对外发言人） |
| 技术面官 | `TECH-OFFICER` | `technical-interview-officer` | 用技术题与追问验真伪、量深度 | 候选人（仅在技术段发言） |
| HR 面官 | `HR-OFFICER` | `hr-interview-officer` | 看动机、稳定性、协作与文化匹配 | 候选人（仅在 HR 段发言） |
| 评估官 | `ASSESSOR` | `talent-assessment-specialist` | 汇总五维分、校准、出报告与结论 | **不接触候选人** |

> 说明：技能包原本把「流程调度」与「破冰接待」拆成两个 Agent。本方案按实践要求合并为**初面官**，以避免校招场景下角色过多、交接噪声过大；合并后仍保留两道内部状态（`CHAT_ACTIVE` / `IDLE`），不破坏单发言人规则。

## 二、角色卡

### 2.1 初面官（ORCH-INIT）

**使命**：保证流程正确、材料真实、候选人体验稳定，并对「是否值得进入深面」给出第一道判断。

| 项目 | 内容 |
|---|---|
| 主责 | ① 候选人信息登记与身份核验；② 公司/岗位介绍与流程说明；③ 简历与到岗信息初核；④ 破冰与表达初评；⑤ 全程计时、控场、异常兜底；⑥ 汇总交接包 |
| 输入 | 候选人姓名/邮箱/院校/专业/毕业时间；简历；岗位投递记录；`01-岗位画像.md`；`02-面试题库.md` 中 H01、P01 |
| 输出 | 候选人档案（结构化）；初面 2 题得分；表达/动机初评；流程状态日志 |
| 交接物 | **H1 候选人档案**、**H2 初面评分单**、**H3 流程状态与异常记录** |
| 禁区 | 不问技术深度题；不给最终录用结论；不透露其他候选人信息；不承诺薪资 |
| 关键闸门 | 材料造假、院校/毕业时间与投递信息冲突、明确无法到岗 → 标记 `SCREEN_FAIL`，可终止流程 |

**初面必做四件事**
1. 用统一话术确认姓名、院校、专业、毕业时间、可到岗日期、工作地点接受度。
2. 用 60 秒讲清公司与岗位（只讲事实，不夸大）。
3. 问 H01（自我介绍+动机）与 P01（项目深挖），各 1–5 分。
4. 输出 `CONTROL_RETURN|ORCH_INIT|STATUS_READY` 并把 H1/H2/H3 交给技术面官。

---

### 2.2 技术面官（TECH-OFFICER）

**使命**：区分「真做过」与「背过答案」，测出可培养的技术底子。

| 项目 | 内容 |
|---|---|
| 主责 | ① 按 `02-面试题库.md` 技术类/项目类顺序提问；② 对模糊回答追问（每题最多 2 轮）；③ 逐题 1–5 分并写依据；④ 记录追问中的增量信息；⑤ 给出技术深度、工程能力、学习潜力（技术侧）三维评分 |
| 输入 | H1 候选人档案；H2 初面评分单；`01-岗位画像.md` 必备/加分能力；题库 T01–T13、P01–P09 |
| 输出 | 逐题得分表；追问记录；三维评分与证据；技术面总结评语 |
| 交接物 | **H4 技术评分包**（题号/维度/得分/依据/追问增量/三维分） |
| 禁区 | 不问薪资、家庭、婚育；不评价院校出身；不在 HR 段插话；不修改初面分 |
| 关键闸门 | 连续 3 题 ≤2 分且追问无增量 → 可提前收束，标注 `TECH_WEAK`，但仍须完成交接，不得直接淘汰 |

**技术段固定结构（建议 45 分钟）**
- 0–3 min：确认方向与项目边界。
- 3–30 min：T01、T04、T05、T08、T11 五题，逐题追问。
- 30–40 min：P01 深挖 + 1 道场景题（P03 或 P09）。
- 40–45 min：候选人提问、收束、写评分。

---

### 2.3 HR 面官（HR-OFFICER）

**使命**：判断「愿不愿意来、能不能待住、能不能与人协作」，并给出文化匹配判断。

| 项目 | 内容 |
|---|---|
| 主责 | ① 建立安全感，说明本段不考技术；② 按题库行为类/HR 类提问；③ 对前后矛盾点温和追问；④ 逐题 1–5 分；⑤ 给出沟通表达、学习潜力（HR 侧）、文化匹配评分 |
| 输入 | H1 档案；H4 技术评分包（只读技术评语中的协作/学习线索，不重问技术）；题库 B01–B07、H01–H07 |
| 输出 | 逐题得分表；稳定性与动机判断；风险提示；HR 面评语 |
| 交接物 | **H5 HR 评分包**（题号/维度/得分/依据/风险项/三维分） |
| 禁区 | 不问技术实现细节；不承诺薪资与级别；不追问与岗位无关的隐私；不做学历歧视性判断 |
| 关键闸门 | 出现明确诚信问题、违法风险、双重全职冲突 → 标注 `HR_RED_FLAG` 并升级评估官 |

**HR 段固定结构（建议 30 分钟）**
- 0–2 min：暖场与说明。
- 2–20 min：B01（冲突/优先级）、B02（压力）、H02（规划）、H07（稳定性）四题。
- 20–26 min：针对技术段暴露的学习短板追问 H05。
- 26–30 min：候选人反问、收束、写评分。

---

### 2.4 评估官（ASSESSOR）

**使命**：把三份主观评分变成一份可复核、可对比、可追溯的结论。

| 项目 | 内容 |
|---|---|
| 主责 | ① 完整性校验；② 五维合成；③ 跨角色分差校准（只校准、不臆造）；④ 总分换算与等级判定；⑤ 生成 `05-评估报告.md` 与 `index.html`；⑥ 输出录用建议与待定条件 |
| 输入 | H1、H2、H4、H5；`03-评分表.md`；同批次候选人数据 |
| 输出 | 单人五维分/总分/等级；三人对比表；录用建议；补测清单；看板页面 |
| 交接物 | **H6 评估报告包**（含数据快照与结论） |
| 禁区 | 不与候选人对话；不修改原始题分；不因「缺人」上调分数；不做与岗位无关的推断 |
| 校准权限 | 维度分可在题均分基础上 **±0.2** 内校准；超出必须写明证据并留痕。学习潜力的校招校准上限可放宽至 **+0.4**（需 HR 与技术双证据） |

## 三、端到端流程与交接

```text
[候选人] → 初面官 ──H1/H2/H3──→ 技术面官 ──H4──→ HR面官 ──H5──→ 评估官 ──H6──→ 报告/看板
              │                    │                 │                 │
           入口闸门            技术闸门           诚信/稳定闸门        结论闸门
```

| 阶段 | 状态 | 执行角色 | 时长 | 完成信号 | 产出 |
|---|---|---|---|---|---|
| 0 信息登记 | `COLLECTING_INFO` | 初面官 | 3 min | `PROFILE_READY` | H1 |
| 1 公司与岗位说明 | `SHOWING_BROCHURE` | 初面官 | 3 min | `BROCHURE_DONE` | — |
| 2 破冰 + 初面 | `CHAT_ACTIVE` | 初面官 | 12 min | `CONTROL_RETURN\|ORCH_INIT\|STATUS_READY` | H2/H3 |
| 3 技术面 | `TECH_ACTIVE` | 技术面官 | 45 min | `CONTROL_RETURN` + `TECH_SCORING_DATA` | H4 |
| 4 HR 面 | `HR_ACTIVE` | HR 面官 | 30 min | `CONTROL_RETURN` + `HR_SCORING_DATA` | H5 |
| 5 评估出报告 | `ASSESSMENT_ACTIVE` | 评估官 | 15 min | `REPORT_READY` | H6 |
| 6 归档 | `COMPLETE` | 评估官 | 5 min | `ARCHIVED` | 报告 + 看板 |

**硬性交接规则**
1. 上一个角色未发出 `CONTROL_RETURN`，下一个角色不得激活。
2. 一次只允许一个角色对候选人说话；评估官全程静默。
3. 交接包字段缺失时，评估官有权退回，不得猜填。
4. 候选人连续两次无响应（30 s + 20 s），按「未作答」记最低档并继续，不中断整场流程。
5. 任何角色发现材料造假，立即冻结流程并交评估官登记，不得私下处理。

## 四、交接物规范

| 编号 | 名称 | 产出者 | 接收者 | 必填字段 | 载体 |
|---|---|---|---|---|---|
| H1 | 候选人档案 | 初面官 | 技术面官、HR 面官、评估官 | 姓名、院校、专业、毕业年份、联系方式、可到岗日、地点接受度 | 结构化文本 |
| H2 | 初面评分单 | 初面官 | 技术面官、评估官 | H01/P01 得分、依据、表达初评 | Markdown 表 |
| H3 | 流程状态与异常 | 初面官 | 全体 | 阶段、时间戳、异常码、处理动作 | 日志行 |
| H4 | 技术评分包 | 技术面官 | HR 面官、评估官 | 题号、维度、1–5 分、依据、追问增量、技术深度/工程能力/学习潜力（技术侧） | Markdown 表 |
| H5 | HR 评分包 | HR 面官 | 评估官 | 题号、维度、1–5 分、依据、沟通表达/学习潜力（HR 侧）/文化匹配、风险项 | Markdown 表 |
| H6 | 评估报告包 | 评估官 | 招聘决策人 | 五维分、加权总分、等级、建议、补测项、数据快照 | 报告 + 看板 |

**信号格式（与技能包保持一致）**

```text
PROGRESS_REPORT|QUESTION_X|TOTAL_X|SCORE_X|JUSTIFICATION_简短原因
CONTROL_RETURN
TECH_SCORING_DATA|姓名|岗位|得分列表|总分|平均分|记录路径
CONTROL_RETURN
HR_SCORING_DATA|姓名|岗位|得分列表|总分|平均分|记录路径
REPORT_READY|姓名|岗位|综合总分|综合评级|报告路径
```

> 本实践把技能包的 0–10 分制统一换算为 **1–5 分制**（`1–5 分 = 原分 ÷ 2`，四舍五入到 0.5），以便五维加权；原始 0–10 分仍保留在附录中可追溯。

## 六、异常与仲裁

| 异常 | 触发条件 | 处理角色 | 处理动作 | 记录 |
|---|---|---|---|---|
| `SCREEN_FAIL` | 材料造假、信息冲突、明确不能到岗 | 初面官 | 终止流程，礼貌结束 | H3 |
| `TECH_WEAK` | 连续 3 题 ≤2 分 | 技术面官 | 收束技术段，正常交接 | H4 |
| `HR_RED_FLAG` | 诚信问题、双重全职、违法风险 | HR 面官 | 升级评估官，暂缓结论 | H5 |
| `DATA_INCOMPLETE` | 交接包缺关键字段 | 评估官 | 退回补录，不猜填 | H6 |
| `SCORE_GAP` | 同一维度两位评分人分差 ≥1.0 | 评估官 | 回看证据，取有证据一方；仍无法判定则记区间并标注 | H6 |
| `NO_RESPONSE` | 两次超时 | 当前面试官 | 记 1 分「未作答」，继续流程 | H3/H4/H5 |

**仲裁原则**：证据优先于印象；原始题分优先于维度校准；候选人体验优先于流程速度；存疑时给「待定 + 补测项」，不做无依据淘汰。

## 八、本实践的取舍说明

1. **四角色而非五角色**：把技能包的「编排器」与「接待官」合并为初面官，减少校招短流程中的交接次数，同时保留唯一对外发言人。
2. **技术面 70% / HR 面 30% 的旧口径不直接沿用**：本实践按岗位画像改为五维加权（见 `03-评分表.md`），更适配校招生「潜力 > 现成经验」的特点。
3. **所有题目可溯源**：题库中 19/37 题直接来自知识库或由知识库题转译，转译题保留原题号，保证面试官可回查原始考察目的与参考答案。
4. **评估官不接触候选人**：避免「又当运动员又当裁判」，保证分数校准的独立性。
