## 二、岗位定位

**岗位名称**：后端开发工程师（校招 / 初级）
**所属部门**：研发中心 · 后端开发部
**汇报对象**：后端组长 / 技术主管
**晋升通道**：初级工程师 → 中级工程师 → 高级工程师 → 技术专家 → 首席技术顾问（技术线，见简章「职业发展通道」）
**岗位一句话**：把 RAG 知识库、Agent 调度与政企业务需求，落成**可部署、可审计、可维护**的后端服务。

### 2.1 岗位职责

1. **知识库后端服务开发**：参与企业智能知识库的文档接入、解析任务编排、切片入库、检索接口、问答会话管理等服务端模块开发。
2. **Agent 与模型服务对接**：开发工具调用网关、任务队列、回调与超时重试机制，封装大模型/向量库/OCR 等外部能力，保证调用稳定与可观测。
3. **政企业务系统开发**：参与进销存、生产管理、CRM、园区管理等系统的接口、权限、审批流、报表数据服务开发。
4. **数据与接口设计**：在指导下完成表结构设计、索引设计、REST/内部 RPC 接口设计，编写接口文档与数据字典。
5. **私有化部署与交付支持**：编写部署脚本与配置说明，配合实施完成内网离线部署、数据迁移、升级回滚、现场问题排查。
6. **质量与协作**：编写单元测试，参与代码评审，修复缺陷，沉淀可复用的技术组件与排障手册。

### 2.2 入职 6 个月的关键成功标准

| 时间 | 期望产出 | 判定方式 |
|---|---|---|
| 第 1 个月 | 独立完成小需求（单表 CRUD + 接口 + 单测），跑通本地与测试环境 | 需求按时交付、代码评审一次通过率 ≥70% |
| 第 3 个月 | 独立负责一个知识库/业务模块的迭代，能定位常见线上问题 | 无 P1/P2 事故；平均排障时长 ≤2 h |
| 第 6 个月 | 参与一次私有化交付，能独立写部署与回滚文档；产出 1 个复用组件 | 交付验收通过；组件被同组复用 |

## 三、必备能力（Must-have）

> 校招不要求精通，但要求**基础扎实、能讲清原理、动手做过**。

### 3.1 编程与计算机基础

| 能力项 | 合格线（3 分） | 优秀线（4–5 分） |
|---|---|---|
| 一门主力语言（Java / Go / Python / Node.js 任一） | 语法熟练，能写清晰的分层代码 | 理解运行时特性（内存、并发、异常、GC/事件循环）并能举例 |
| 数据结构与算法 | 数组/链表/哈希/栈队列/树/排序查找，能分析复杂度 | 能在业务中做取舍（如用布隆过滤器/堆/并查集）并说明代价 |
| 操作系统与网络 | 进程线程、内存、文件 IO；TCP/HTTP 基础 | 能解释连接复用、TIME_WAIT、阻塞与非阻塞、日志与信号 |
| 数据库 | SQL 熟练；知道索引、事务、范式 | 能读懂执行计划，会做联合索引与慢查询优化，理解隔离级别与锁 |
| Git 与 Linux | 常用命令、分支合并、看日志 | 会排查端口/磁盘/进程/网络问题，能写 shell 脚本 |

### 3.2 Web 与接口

- 理解 REST 语义、状态码、幂等性、分页、鉴权（Session/JWT）、参数校验。
- 能设计一张清晰的接口契约：入参、出参、错误码、超时、重试、幂等键。
- 理解分层（Controller/Service/Repository）、依赖注入、统一异常处理、日志埋点。
- 了解缓存（Redis）常见用法：缓存穿透/击穿/雪崩、过期策略、一致性取舍。

### 3.3 工程与交付

- 会写单元测试，知道边界值、异常分支、Mock 的边界。
- 会用 Docker 起本地依赖，能看懂 CI 流水线。
- 有基本的可观测意识：日志分级、关键指标、链路 ID。
- 能写清楚一份 README：环境、配置、启动、验证、回滚。

### 3.4 业务理解

- 理解「文档 → 解析 → 切片 → 向量化 → 检索 → 生成」的主链路，知道后端在每一段的责任边界。
- 理解私有化项目的约束：内网、离线、数据不出场、权限分级、审计留痕。
- 理解 ToB/ToG 交付：需求确认、验收标准、变更控制、现场支持。

### 5.2 一票否决项

- 简历或项目经历**造假**（无法回答自己写在简历上的内容，且经提示仍无法解释）。
- 明确表示**无法接受**武汉工作地点或校招到岗时间，且无合理协商空间。
- 存在**双重全职**、竞业限制冲突、学历/身份造假等合规问题。
- 出现**歧视、攻击、泄露前雇主机密**等严重职业素养问题。
- 技术基础低于「能独立完成 CRUD + 单测」的下限，且学习意愿与学习能力均不足。

> 否决项由 HR 面官发起、评估官登记，需有原文记录，不得仅凭印象。

## 七、岗位画像使用说明

1. **面试前**：技术面官按「必备能力」表挑选 5 道技术题，确保覆盖语言/数据/接口/检索/部署五个面。
2. **面试中**：所有判断必须回到行为证据，不使用「感觉聪明」「学校好」等无锚点表述。
3. **面试后**：评估官按五维模型合成，不直接使用「像不像我」的整体印象。
4. **复盘时**：若录用者 6 个月内未达关键成功标准，回溯是画像偏差还是面试效度问题，并更新本文件。
